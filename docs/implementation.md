# Короткий разбор реализации

## Как делал

1. Зафиксировал единственный обязательный end-to-end сценарий: Telegram → API → БД → CRM → тег → фильтр.
2. Взял архитектурные принципы из собственного проекта Nadein Systems: отдельный HTTP API, Telegram как внешний адаптер и единый реестр лидов. Код и доменная модель этого репозитория собраны заново под тестовое, без переноса истории исходного проекта.
3. Сначала реализовал модель `Lead`/`Tag` и API, затем покрыл основной контракт тестами.
4. После API добавил Telegram FSM для трёх шагов — имя, контакт, запрос.
5. Последним слоем сделал web-интерфейс CRM и проверил сквозные сценарии вручную и через pytest.

## AI-инструменты

Использовал ChatGPT как coding-agent для декомпозиции, черновой генерации кода и ревью граничных случаев. Ключевые решения — общий API для всех источников, `external_id` для идемпотентности Telegram, отдельная many-to-many модель тегов и сознательный отказ от MTProto в обязательном MVP — принимались после проверки требований задания.

Примеры запросов к AI:

- «Разложи тестовое на минимальный сквозной сценарий, который можно полностью проверить за три дня».
- «Проверь API-модель лидов на идемпотентность, гонки и возможность добавить второй источник».
- «Сделай code review: где переусложнено для MVP и что можно убрать без потери обязательных сценариев».
